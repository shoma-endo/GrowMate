PR を作る直前の最終判定です。現在のコードと前段の報告から、対象仕様書の要件充足と前段の指摘の解消状態を判定してください。コードは編集しません。

1. 対象仕様書（添付 `plan.md` の `対象仕様書:` 行のパス）の要件を独立に判定できる単位へ分け、現在のコードの `path:行番号` へ対応付ける。前段の報告と現在のコードが食い違う場合は現在のコードを優先する。
2. 前段の指摘（`review-gate.md` / `self-review.md`）が解消済みかを、実コードを開いて確かめる。
3. UI 変更がある場合（`ui-evidence.md` が `captured`）は、対象画面と既存の類似画面のスクリーンショットを同じ画面幅どうしで Read で開いて見比べ、対象画面のはみ出し（表の値）と見た目の差を判定の根拠に含める。根拠には画面・画面幅・スクリーンショットのパスを書く。
4. 判定:
   - `APPROVE`: 要件がすべて充足し、未解消の問題が無い。
   - `REJECT`: コード変更で閉じられる未充足要件・未解消の問題がある。修正対象・受入条件・最小の修正境界を `path:行番号` 付きで書く。
   - `BLOCKED`: 現在のコードと前段の報告だけでは判定できず、タスク範囲のコード変更では必要な情報を得られない。
- 根拠（`path:行番号`、またはスクリーンショットのパス）の無い充足・未充足の判定は書かない。
