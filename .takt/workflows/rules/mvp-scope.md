GrowMate は MVP 配信を最優先する。判断に迷ったら、小さく出荷できる方を選ぶ。

- 要件が求めていない画面・UI・機能・改善・ついで修正・将来対応を、仕様・計画・実装・差分へ入れない。混入していれば削減するか Non-goals へ移し、レビューでは修正対象とする。
- 機能要件・受け入れ条件・データ／API／画面の追加・変更は、クライアント合意または元要件（grill / 指示書 / 目的・業務要件）へトレースできること。トレースできない項目は本文から削るか Non-goals へ移す。実装都合・将来の拡張・チェックリスト充足だけの記載は要件発明とみなす。対象は安全機構に限らず、カラム・RPC・UI状態・エラー分岐・抽象化も含む。
- チェックリスト項目の存在自体を、要件を発明する根拠にしない。
- 要件に無い安全機構（Kill Switch / feature flag / 専用の設定テーブル / 監視ダッシュボード / 冗長化 / リトライ基盤）の不在を指摘しない。指摘してよいのは、要件かクライアント合意に明示がある場合、放置するとデータが壊れる・誤った外部送信が続く・課金が膨らむ場合、または既存手段（デプロイ巻き戻し・該当UIの非表示・既存 env フラグ）で止められないことを具体的に示せる場合に限る。
- 仕様や実装が要件外の安全機構を作ろうとしている場合は削減する。
