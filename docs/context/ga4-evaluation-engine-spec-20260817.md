02計算式
コピー
期待読了時間（分） = 本文文字数 ÷ 500
    ※500字/分は日本語の平均的な黙読速度
    ※画像・表が多い記事は  期待読了時間 += (画像点数 × 3秒) で補正

平均エンゲージメント時間（秒） = userEngagementDuration ÷ activeUsers
    ※GA4「ページとスクリーン」の平均エンゲージメント時間と同じ定義
    ※averageSessionDuration は使わない（GA4画面と数値が合わなくなる）

読了率 = 平均エンゲージメント時間 ÷ (期待読了時間 × 60)

読み始め率 = GA4の engagementRate をそのまま使用
    ※必ず landingPage 次元で取得する（pagePath だとセッション指標が歪む）

完読率（任意・精度向上用） = scroll イベント数(90%到達) ÷ sessions
    ※GA4の拡張計測がONなら追加設定なしで取得できる
評価対象の足切り
セッション30未満のページは評価を出さず「データ蓄積中」と表示する。少数セッションで滞在10分と出て優良記事と誤判定するのが、この手の指標の最大の事故。

def score(value, anchors):
    if value <= anchors[0][0]:
        return 0
    if value >= anchors[-1][0]:
        return 100
    for (x1, y1), (x2, y2) in zip(anchors, anchors[1:]):
        if value <= x2:
            return round(y1 + (value - x1) / (x2 - x1) * (y2 - y1))
上限は100で頭打ちにするが、アンカーの最上段（読了率50% / 読み始め率80%）を実質到達困難な水準に置いてあるため、優良ページ同士の差もきちんと点数に出る。

06メディア全体スコア
記事単位の点数を積み上げて、メディア全体の資産価値を1つの数字にする。月次で上がっていくのを見せることが、このツールの継続利用の理由になる。
資産価値スコア = 全記事のコンテンツ力スコアの単純平均
実効スコア     = セッション数で重み付けした加重平均
2つ出すことに意味がある。
関係
意味
打ち手
実効 > 資産価値
良い記事に流入が集中している。健全
低スコア記事の整理（統合・削除）で資産価値を引き上げる
実効 < 資産価値
悪い記事に流入が集中している。危険
流入上位の低スコア記事を最優先で改善
あわせて全記事を散布図にプロットする（横軸＝読み始めスコア、縦軸＝読了スコア、点の大きさ＝セッション数）。右上が資産、左下が負債。点群が月次で右上に移動していくのが改善の証明になる。
07LLMプロンプト
システムプロンプト
コピー
あなたはコンテンツマーケティングの改善コンサルタントです。
Webサイトの記事1本について、計測データと判定結果を受け取り、
サイト運営者向けの診断コメントを書きます。

【読者の前提】
- 相手はGA4を見ません。専門用語を一切知りません。
- 「エンゲージメント率」「セッション」「直帰率」などの用語は出力に使わないでください。
- 数値は「率」ではなく「人数」と「時間」で語ってください。

【書き方のルール】
- 断定して書きます。「可能性があります」「かもしれません」は使いません。
- 診断は事実のみ。推測を混ぜる場合は「と考えられます」を1文だけ許容します。
- 次の一手は1つだけ挙げます。複数挙げると実行されません。
- 次の一手は今日着手できる具体的な作業にします。「改善しましょう」は禁止です。
- 記事の内容そのものに触れられる場合は触れてください（タイトルや見出しを引用する）。
- 1文は60字以内。全体で200字以内。
- 波ダッシュは使わず、「から」または読点で表現します。

【点数の意味（全指標共通）】
80-100 良好 / 60-79 合格ライン / 40-59 改善の余地あり / 20-39 要改善 / 0-19 深刻

【診断コードの意味】
- R_TOP_EXIT   : 冒頭で帰られている。書き出しの問題
- R_MISMATCH   : 読む人は深く読むが、来た人の多くがすぐ帰る。集客キーワードと中身のズレ
- R_MID_EXIT   : 読み始めたが途中で離脱。見出し構成と本文の密度の問題
- R_SKIM       : 拾い読みで終わっている。結論の位置と情報密度の問題
- R_GOOD       : 読まれている。読了面の改善は不要。次はCTAとオファーの検証へ
- R_LOWDATA    : データ不足。判定しない

出力は指定のJSON形式のみ。前置きや解説は書きません。

狙い: 読み始めスコアを46点から80点へ
点数はバー付きで出す。数字だけだと大小の実感が湧かない。サイト内順位を添えると「自分のサイトの中で何番目に悪いか」が分かり、着手判断が速くなる。
「読了率12%」を「38人が最後まで読んだ」と換算してはならない。読了率は平均時間の比であり、人数比ではない。最後まで読んだ人数を出す場合は、GA4拡張計測の scroll イベント（90%到達）の実測値を使う。取得できない場合は人数を出さず「1人あたり平均で全体の12%まで読まれています」と表記する。
推定値を実測のように見せると、クライアントが他ツールと突き合わせた瞬間に信用を失う。
生の数値（平均エンゲージメント時間、読み始め率）は、GA4の画面と一字一句一致させる。クライアントは必ず一度は突き合わせる。ここが合っていることが、以後GA4を見なくなる条件になる。
