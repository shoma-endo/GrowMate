# 手動検証チェックリスト

自動検証は [`SKILL.md`](SKILL.md) の基本フローで完了させる。ここでは、変更した画面・機能を実際に操作して確認する。

## UI統一性（UI変更時のみ）

[`growmate-ui-ux`](../growmate-ui-ux/SKILL.md) のデザインシステムと、同種の既存画面に沿っていることを確認する。

- 既存の `src/components/ui/` のコンポーネントを再利用し、同じ役割の独自UIを増やしていない。
- 色・半径・グラフは既存のセマンティックトークンを使い、生の Tailwind 色や独自フォント指定を増やしていない。
- 見出し・本文・ボタン・エラー・空状態の文言と表記が既存画面と統一され、ユーザー向けに不要な英語ラベルがない（→ 下記「表示文言の表記統一」）。
- 通常・ローディング・成功・失敗・空状態で、既存画面と同じ情報の出し方・操作導線になっている。
- コントラスト、focus-visible、フォーム label、aria-label、タッチターゲットを確認する。

## 表示文言の表記統一（UI 文言を追加・変更したときのみ）

正本は [`growmate-ui-ux/ui-text.md`](../growmate-ui-ux/ui-text.md)。対象は画面に出る文字列（JSX テキスト、ボタン、placeholder、toast、`ERROR_MESSAGES`、`aria-label`、メタデータ）。変数名・関数名は対象外（→ `project-naming`）。

まず `npm run verify:ui-text` を通す。用語辞書違反・三点リーダ・進行中表現・漢字かな・長音・感嘆符・絵文字はここで落ちる。

その上で、**機械判定できない次の 4 点を目で確認する**。

- **同一画面での用語一貫性**: 同じ対象を 1 つの語で呼んでいる（「連携」と「接続」を混在させていない）。既存の同種画面とも揃っている。
  - 辞書で「機械チェック = 目視」の語（`接続` `解除` `再認証` 等）はスクリプトが見ないので、ここで必ず確認する。
  - **辞書に無い新しい言い方**はスクリプトを素通りする。見つけたら `ui-text.md` の用語辞書に行を足す（足せば次回から自動で検査される）。
- **略語の初出**: `GSC` 等の略語を使う画面で、見出しか説明文にフル表記（`Google Search Console`）が既出になっている。
- **句点**: 1 文の通知・ラベル・ボタンは句点なし、2 文以上は全文末に句点あり。「1 文目だけ句点あり」になっていない。
- **英字と日本語の間の半角スペース**: `GA4 連携ガイド` のように 1 つ入れる。同じ画面内で入れたり入れなかったりしていない。

新しい語を導入した場合は、コードに書く前に `ui-text.md` の用語辞書へ追記したかを確認する。

## 画面・機能ごとのチェックポイント

- **認証周り**
  - `app/page.tsx` から認証フローを一通り通して、認証状態に応じた表示切り替えが期待通りか確認する。
  - ログイン／ログアウトなど代表的な認証状態での動作を意識する。

- **WordPress 連携変更時**
  - `/analytics` 画面で WordPress から取得した投稿が正しく表示されるか確認する。
  - `AnnotationPanel` での表示・保存動作（`content_annotations` への upsert）が正常に動くかを確認する。
  - `/wordpress-import` でのインポートフローがエラーなく完了するか確認する。

- **チャット / Canvas 変更時**
  - `/chat` でメッセージ送信 → ストリーミング応答 → Canvas への反映が一連で動くか確認する。
  - セッションの作成・切替・削除、および Canvas の編集・保存が正常に動くか確認する。

- **Google Ads 連携変更時**
  - `/setup/google-ads` で連携設定・再認証フロー（`needsReauth` 時の導線）が動作するか確認する。
  - `/google-ads-dashboard` で取得データ・AI 分析結果が表示されるか確認する。

- **GSC 連携変更時**
  - `/gsc-dashboard` で Search Console から取得したデータが表示されるか確認する。
  - `/gsc-import` でのインポートフローがエラーなく完了し、意図した範囲のデータが取り込まれているか確認する。

- **GA4 連携変更時**
  - GA4 プロパティおよびイベント設定画面で設定内容が正しく反映されるか確認する。
  - 日次同期やイベント集計に関わる変更の場合は、対象期間のメトリクスが期待通りになるかを確認する。

- **オンボーディング / 事業情報変更時**
  - `/business-info` で入力・保存・再表示が正常に動くか確認する（初回フローの仕様は `docs/plans/*` を正本とする）。

- **権限まわり**
  - `/admin/users` でロール更新が反映されることを確認する。
  - `admin` / `paid` / `trial` / `unavailable` でアクセス制御（特に `/admin/*`, `/analytics`, `/setup/*`）が期待通り動作することを確認する。
