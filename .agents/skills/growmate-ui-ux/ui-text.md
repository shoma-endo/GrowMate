# UI 文言の表記統一

**UI 上に表示される文言の表記揺れを防ぐための正本**。変数名・関数名・ファイル名の規約は対象外（→ `project-naming`）。

GrowMate は同じ操作・同じ状態を複数画面で見せる。同じ意味を画面ごとに違う言い方で書くと、初心者ユーザーは「別の機能では？」と迷う。表記統一は装飾ではなく**誤解を防ぐ機能**として扱う。

## 対象範囲

| 区分 | 対象か | 具体例 |
|------|--------|--------|
| JSX のテキストノード | ✅ | `<CardTitle>連携ステータス</CardTitle>` |
| ボタン・ラベル・placeholder | ✅ | `<Button>保存</Button>`, `placeholder="URL を入力"` |
| toast / 通知 | ✅ | `toast.success('保存しました')` |
| エラーメッセージ定数 | ✅ | `src/domain/errors/error-messages.ts`, `ChatError.ts` |
| `aria-label` / `title` / `alt` | ✅ | スクリーンリーダーが読み上げる = ユーザー向け文言 |
| ページメタデータ | ✅ | `metadata.title`, `description` |
| コード内コメント・`console.*` | ❌ | 開発者向け。統一の対象外 |
| 変数名・型名・DB 列名 | ❌ | → `project-naming` |
| LLM プロンプト（`src/lib/prompts.ts`） | ❌ | AI への指示文であり画面表示ではない |

## 用語辞書

同じ対象は必ず同じ語で呼ぶ。左（正）以外を UI に書かない。

**この表が唯一の正本**。`scripts/check-ui-text.sh` はこの表を読んで検査ルールを生成するので、スクリプト側に用語を書き足す必要はない。行を足せばそのままチェックが効く。

| 正 | 使わない表記 | 機械チェック | 補足 |
|----|-------------|------------|------|
| Google Ads | Google広告、グーグル広告、GoogleAds | ✅ | 製品名は提供元の英字表記に合わせる |
| Google Search Console | サーチコンソール、Google Search console | ✅ | 略称 `GSC` は下記「略語」に従う |
| GA4 | Googleアナリティクス4、GoogleAnalytics4、GA-4 | ✅ | フル表記は `Google Analytics 4`。初出はフル表記、以降 `GA4`（→「略語」） |
| WordPress | Wordpress、ワードプレス | ✅ | 大文字 P |
| ログイン / ログアウト | サインイン、サインアウト | ✅ | |
| 事業者情報 | 事業情報、ビジネス情報 | ✅ | `/business-info` の呼称 |
| 評価 | GSC評価 | ✅ | Google Search Console 由来の評価。修飾を付けず「評価」と呼び、文脈は見出しで示す（`/gsc-dashboard` の「評価を開始」「評価基準日」に合わせる）。Google Ads 側の評価を UI に出す場合は両方に修飾を付けて揃える |
| 連携 | 接続、コネクト、リンク | 目視 | 外部サービスとつなぐ操作は一貫して「連携」。「接続」「リンク」は一般語で誤検出が出るため機械チェックしない |
| 連携解除 | 解除、切断、連携を切る | 目視 | 「解除」が正表記「連携解除」に含まれるため機械チェックしない |
| 再連携 | 再認証、再接続 | 目視 | ユーザー向けは「再連携」。`needsReauth` は識別子なので変更不要。「再認証」はコード・仕様で頻出のため機械チェックしない |

### 行の書き方

| 列 | ルール |
|----|--------|
| 正 | UI に書いてよい唯一の表記 |
| 使わない表記 | `、` または `/` 区切りで列挙。**機械チェックの有無に関わらず全て書く**（人のレビュー用の正本でもあるため） |
| 機械チェック | `✅` = この行の「使わない表記」を全て検査対象にする / `目視` = 検査しない |
| 補足 | `目視` にした場合はその理由を必ず書く |

`目視` にするのは、その語が**コードや別の意味の UI 文言で正当に使われる**とき（`接続`、`解除`、`再認証` など）。誤検出を出すルールはチェック自体を無視される原因になるので入れない。判断に迷ったら `目視` にして `quality-gate` の手動確認に回す。

### 略語

`GSC` のような略語は**その画面での初出でフル表記＋括弧書き**し、以降は略語を使う。

- ✅ `Google Search Console（以下、GSC）` → 同一画面の 2 回目以降は `GSC`
- ❌ 初出がいきなり `GSC評価未開始`（初心者には読み解けない）

ボタン・フィルタチップなど**短さが要るラベル**で略語を単独で使う場合は、同じ画面内の見出しまたは説明文でフル表記が既出であることを確認する。

## 表記ルール

### 1. 句点

| 文言の形 | 句点 | 例 |
|----------|------|-----|
| 1 文で完結する通知・ラベル・ボタン | 付けない | `保存しました` / `データの取得に失敗しました` |
| 2 文以上 | すべての文末に付ける | `書き出し案を保存しました。見出し生成ボタンで1つ目の見出しを生成してください。` |

「1 文目に句点があるのに末尾だけ無い」は不可。

### 2. 三点リーダ

用途で使い分ける。混在させない。

| 用途 | 記号 | 例 |
|------|------|-----|
| 進行中・待機を示す | 半角ピリオド 3 つ `...` | `保存中...` / `自動で再試行しています...` |
| 長い文字列を途中で切る | `…`（U+2026） | `${text.slice(0, 140)}…` |

- ❌ `保存中…`（進行中に `…` を使わない）

### 3. 進行中の状態表現

スピナー・ボタン・toast の**ラベル**は `<動詞>中...` の形に統一する。`です` を挟まない。

- ✅ `保存中...` / `読み込み中...` / `取得中...` / `送信中...` / `生成中...` / `削除中...`
- ❌ `保存中です...` / `取得中です`

対象はラベルのみ。説明文の一部として文中に出る場合は普通の日本語で書く。

- ✅ `このアカウントは削除処理中です。時間をおいてもう一度お試しください。`

### 4. エラー時の復帰導線

再操作を促す文は `もう一度お試しください` に統一する（`再度お試しください` は使わない）。ボタンのラベルは `再試行`。

- ✅ `認証セッションの有効期限が切れました。もう一度お試しください。`

### 5. 漢字・かな

補助的に使う語はひらく。

| 正 | 使わない表記 |
|----|-------------|
| ください | 下さい |
| できる / できます | 出来る / 出来ます |
| ない場合 | 無い場合 |
| ため | 為 |

### 6. 長音・カタカナ

JIS Z 8301 に従い、語尾の長音符を省略しない。

- ✅ `サーバー` / `ユーザー` / `フォルダー` ❌ `サーバ` / `ユーザ`

### 7. 英字と日本語の間

半角英数字と日本語の境界に半角スペースを 1 つ入れる。

- ✅ `GA4 連携ガイド` / `WordPress 設定ガイド` ❌ `GA4連携ガイド` / `WordPress設定ガイド`
- 例外: 助詞が直後に来る場合はスペース不要（`WordPress の投稿` は入れる、`WordPressの投稿` は不可 → 前者に統一）
- 括弧・句読点の前後には入れない（`Google Ads（連携済み）`）

### 8. 記号

- 括弧は全角 `（）`。半角 `()` は英字のみで構成される場合に限る。
- 感嘆符 `!` `！` は使わない。成功通知も事実を述べる（`保存しました`、`保存しました！` は不可）。
- 絵文字を UI に使わない（アイコンは lucide-react。SKILL.md のデザインシステム参照）。

### 9. 文体

敬体（です・ます）で統一する。ラベル・ボタン・見出しは体言止めまたは動詞の言い切り（`保存`、`連携を解除`）。

## 新しい語を足すとき

1. 上の用語辞書を引き、既存語で言えるならそれを使う。
2. 既存語で言えない新概念なら、**辞書に 1 行追記してからコードに書く**。辞書に無い語を先にコードへ入れない。
   追記した行はそのまま `npm run verify:ui-text` の検査対象になる。スクリプトを触る必要はない。
3. 既存語の言い換え（`連携` → `接続` 等）を思いついた場合、単独で変えない。全画面を一括で変えるか、変えないかの二択。

**チェックが自動で追いつかないもの**: 辞書に登録されていない新しい言い方（例: 誰かが「ダッシュボード」を「管理画面」と書き始める）は素通りする。これは機械には判定できないので、`quality-gate` の手動確認で「同種の既存画面と同じ語か」を見て拾い、見つけたら辞書に行を足す。

## 検証

`npm run verify:ui-text`（`scripts/check-ui-text.sh`）で、機械判定しても誤検出が出ない項目だけを検査する。

| 検査対象 | ルールの置き場所 |
|----------|-----------------|
| 用語（`Google広告` → `Google Ads` 等） | **本ファイルの用語辞書**。スクリプトが起動時にテーブルを読んで生成する |
| 表記ルール（進行中表現、`…`、復帰導線、漢字かな、長音、感嘆符、絵文字） | `scripts/check-ui-text.sh` の `RULES`。語の対応表では表せないため |

検査しないもの: 英字と日本語の間のスペース、句点、略語の初出、文体、同一画面での用語一貫性。これらは `quality-gate`（[`manual-testing.md`](../quality-gate/manual-testing.md)）の手動確認で見る。

pre-commit では staged 済みの `app/**` `src/**` の `.ts` / `.tsx` のみを対象に自動実行される（既存の未修正分で commit が止まらないようにするため）。このとき `--staged` を付けて**インデックスの内容**を検査する。ファイル名だけ渡してワークツリーを見ると、`git add -p` で一部だけステージした場合に、実際にコミットされる内容と検査対象がズレる。

**「検査できなかった」を「問題なし」と報告しない**こと。次の場合はいずれも成功ではなく**失敗**する。

- `ripgrep`（`rg`）が無い — 全ての検索が空振りし、違反ゼロとして緑になってしまうため。日本語の文字クラスと `\x{...}` を正しく扱う必要があるので `rg` を必須依存とする
- 辞書が読めない／1 件もルールを生成できない — テーブル形式を壊したときに検査ゼロ件で緑になるのを防ぐため

`RULES` に表記ルールを足すときは、コメント・`console.*`・正規表現リテラル・識別子にマッチしないことを確認する。誤検出を出すルールは、チェック自体を無視される原因になるので入れない。
